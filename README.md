# Извлечение определений из TXT/PDF и выгрузка в Excel

Программа на Python предназначена для автоматического извлечения определений из текстовых файлов и PDF-документов. После обработки программа формирует итоговый Excel-файл с найденными определениями, источниками и результатами автоматической классификации по степени полноты и формальной записываемости.

## Возможности программы

* загрузка текстовых файлов из папки `sources/texts`;
* загрузка PDF-файлов из папки `sources/pdf`;
* очистка текста от лишних пробелов, переносов и служебных символов;
* извлечение определений по специальной разметке вида `[D001]`;
* автоматический поиск определений по ключевым словам, если разметка отсутствует;
* определение примерного термина из текста определения;
* автоматическая классификация определений по трём категориям;
* сохранение всех найденных данных в Excel-файл;
* сохранение дополнительного JSON-файла с результатами;
* формирование краткого отчёта о запуске программы.

## Структура программы

Основная логика программы разделена на классы:

* `SourceText` — хранение информации об исходном документе;
* `Candidate` — хранение найденного определения до классификации;
* `DatasetRecord` — итоговая запись для выгрузки;
* `TextNormalizer` — очистка текста от лишних символов и переносов;
* `SourceCollector` — загрузка TXT и PDF-файлов;
* `DefinitionExtractor` — извлечение определений из текста;
* `TermExtractor` — попытка выделить термин из определения;
* `RuleAnnotator` — автоматическая классификация определения;
* `DatasetAssembler` — сбор итоговых записей;
* `Exporter` — сохранение результатов в Excel, JSON и summary-файл;
* `Application` — общий сценарий работы программы.

Основной файл программы:

```text
main.py
```

## Категории классификации

Программа автоматически относит каждое найденное определение к одной из трёх категорий:

| Категория         | Значение                                                                                 |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `SELF_CONTAINED`  | определение самодостаточное и может быть формализовано сразу                             |
| `NEEDS_PRIOR_DEF` | определение требует дополнительного контекста, ранее введённых обозначений или уточнений |
| `INFORMAL`        | определение содержит оценочные или нестрогие признаки                                    |

## Требования

Для запуска потребуется:

* Python 3.10 или новее;
* PyMuPDF;
* openpyxl.

## Установка библиотек

В терминале в папке проекта выполнить:

```bash
pip install PyMuPDF openpyxl
```

## Подготовка файлов

В корне проекта необходимо создать папку `sources`, а внутри неё две папки:

```text
project/
├── main.py
├── sources/
│   ├── texts/
│   │   └── input.txt
│   └── pdf/
│       └── input.pdf
└── output/
```

Назначение папок:

* `sources/texts` — папка для текстовых файлов `.txt`;
* `sources/pdf` — папка для PDF-документов;
* `output` — папка, куда программа сохраняет результаты.

Папка `output` создаётся автоматически, если её нет.

## Формат входных данных

Самый надёжный способ подготовки текста — использовать разметку определений:

```text
[D001] Группой называется множество с ассоциативной бинарной операцией, нейтральным элементом и обратным элементом для каждого элемента.

[D002] Кольцом называется множество с двумя бинарными операциями, сложением и умножением, удовлетворяющими заданным аксиомам.
```

Каждое определение должно начинаться с идентификатора:

```text
[D001]
[D002]
[D003]
```

Если такой разметки нет, программа пытается найти определения автоматически по словам:

* `определение`;
* `называется`;
* `называются`;
* `будем называть`;
* `назовём`;
* `defined as`;
* `is called`.

## Результаты работы

После запуска в папке `output` формируются файлы:

```text
Definitions_Review.xlsx
definitions_dataset.json
run_summary.json
```

Назначение файлов:

* `Definitions_Review.xlsx` — основной итоговый Excel-файл с извлечёнными определениями;
* `definitions_dataset.json` — полный результат обработки в формате JSON;
* `run_summary.json` — краткая сводка по запуску программы.

## Структура итогового Excel-файла

В файле `Definitions_Review.xlsx` формируются следующие столбцы:

| Столбец            | Назначение                               |
| ------------------ | ---------------------------------------- |
| `id`               | идентификатор найденного определения     |
| `term`             | автоматически выделенный термин          |
| `definition_ru`    | текст определения                        |
| `source_file`      | имя исходного файла                      |
| `source_kind`      | тип источника: `txt` или `pdf`           |
| `predicted_label`  | автоматически присвоенная категория      |
| `formalizable_now` | можно ли формализовать определение сразу |
| `rule_score`       | оценка уверенности правила               |
| `evidence`         | найденные признаки для классификации     |
| `label_reason`     | причина присвоения категории             |
| `missing_context`  | какой контекст требуется для уточнения   |

## Как проверить качество работы

Для проверки результата необходимо открыть файл:

```text
output/Definitions_Review.xlsx
```

Затем проверить:

1. Все ли нужные определения были извлечены из исходных файлов.
2. Корректно ли заполнен столбец `definition_ru`.
3. Правильно ли указан файл-источник в столбце `source_file`.
4. Не попали ли в таблицу лишние предложения, которые не являются определениями.
5. Насколько корректно программа определила категорию `predicted_label`.
6. Заполнены ли поля `evidence`, `label_reason` и `missing_context`.

Если программа извлекла слишком мало данных, рекомендуется использовать явную разметку `[D001]`, `[D002]`, `[D003]`.

## Возможные проблемы

### Исходные файлы не найдены

Следует проверить, что рядом с `main.py` существует папка:

```text
sources
```

А внутри неё есть хотя бы одна из папок:

```text
sources/texts
sources/pdf
```

Также необходимо проверить, что в этих папках действительно находятся `.txt` или `.pdf` файлы.

### Определения не найдены

Если программа не нашла определения, нужно проверить формат входного текста.

Рекомендуемый формат:

```text
[D001] Текст первого определения.

[D002] Текст второго определения.
```

Если явная разметка не используется, в тексте должны быть слова-маркеры, например `называется`, `определение`, `будем называть`.

### Ошибка при чтении PDF

Если появляется ошибка, связанная с `PyMuPDF`, нужно установить библиотеку:

```bash
pip install PyMuPDF
```

### Ошибка при создании Excel

Если появляется ошибка, связанная с `openpyxl`, нужно установить библиотеку:

```bash
pip install openpyxl
```

### Excel-файл не появился

Следует проверить, что программа была запущена без ошибок. Также нужно убедиться, что в исходных файлах были найдены определения. Если определений нет, Excel-файл не создаётся.

## Итог

В результате работы программа формирует Excel-файл с извлечёнными определениями, автоматически определяет степень их полноты и показывает, можно ли использовать каждое определение для дальнейшей формализации.
